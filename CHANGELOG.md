## [0.4.0] - 2026-11-22

Security baseline. Valid input gives byte-identical results to 0.3.0; only invalid input and one output cell change. Minor version because Python 3.9 support ends (no API change).

### Changed (Python support and dependency floors)

- **Python 3.9 is no longer supported (`requires-python >=3.10`).** Every patched release of `requests` (2.33.0+) and `urllib3` (2.7.0+/2.8.0+) requires Python 3.10, so on Python 3.9 the network extras could only install versions with known advisories. pip on Python 3.9 keeps resolving the previous release.
- **Security floors in the network extras:** `requests>=2.33` and `urllib3>=2.8`. These close CVE-2026-25645 (requests) and CVE-2026-44431, -44432, -97687, -97688 and -97689 (urllib3). `urllib3` is listed directly so that an environment cannot keep an older, vulnerable copy that `requests` alone would accept.

### Fixed

- `analyze_link` refuses a non-finite (`nan`, `inf`) antenna height, frequency or k-factor, and a non-integer `n_samples`, with a `ValueError` naming the field, before any elevation request. In 0.3.0 such input produced a NaN clearance ratio that read as neither clear nor obstructed and sorted unpredictably in a batch. numpy numbers are still accepted.
- `parse_links_csv` reports a row whose numbers are non-finite (`float()` accepts `"nan"` and `"inf"`) as `Row N (id): not a finite number: <columns>, skipped.` instead of passing it on. The `Row N (id)` prefix is unchanged, so callers that parse it keep working.
- `results_to_csv` writes a `link_id` that begins with `=`, `+`, `-` or `@` with a leading apostrophe, so a spreadsheet does not evaluate it as a formula. Plain numbers and "number unit" text are left alone. Same rule as aei-workflow-runner (`csvsafe.py`) and the Velorona Web Map. GeoJSON output is unchanged.
- The Open-Meteo client refuses a response that is not a JSON object, or whose `elevation` field is not a list, with `ElevationDataError` (previously an `AttributeError` or a misleading count error).

### Added

- `SECURITY.md`: reporting policy and the library's security boundaries, controls and tests.
- `batch.csv_text_cell(text)`: the formula guard, usable on its own.

## [0.3.0] - 2026-11-01

Additive: no existing call changes behaviour. `analyze_link(...)` without the new argument is byte-identical to 0.2.1 (same Open-Meteo call, no cache, no retry).

### Added

- **Elevation-provider seam.** `analyze_link(..., elevation_provider=None)` takes any object with a `source` string and `get_elevations(points)`. The result has a new last field, `elevation_source`, naming where the ground heights came from (the Open-Meteo string by default).
- `OpenMeteoProvider`: the online service with an in-memory LRU cache (successful values only), bounded backoff on HTTP 429 / 5xx / timeouts / connection errors (1 s then 3 s, `Retry-After` honoured up to 10 s, a *daily* quota never retried) and a 30 s cool-down after a rate limit that outlasted the retries, so a batch of links does not hammer a service that has just said no. Thread-safe. Cool-down uses a monotonic clock.
- `LocalDEMProvider(sampler, source, dem_crs, sampler_reprojects, bounds)`: heights from a raster the caller reads. Every point must have a value; a point outside the raster, on a nodata cell (None/NaN/inf), or a raster not in WGS84 without reprojection raises `ElevationCoverageError` / `DEMCrsMismatchError` before any result exists. Nothing is substituted, never 0 m.
- Errors: `ElevationCoverageError`, `DEMCrsMismatchError`, `ElevationServiceUnavailable` (carries `transient`, `daily`, `kind`, `status`); all subclass `ElevationDataError` (a `ValueError`). `RetryPolicy`, `classify_failure`.
- `get_elevations(points, timeout, retry=None, sleep=time.sleep)`: retry is opt-in; the default is the historical single attempt.
- Python/JS parity: `tests/fixtures/seam_parity.json` (generated by `make_seam_parity.py`) and `parity/seam_parity.mjs`, which runs the Map's `analyzeLinkFromElevations` (read-only) on the same heights: 4 cases, 216 comparisons, 0 diverging. The JS half is skipped, and reported as skipped, when node or a Map checkout is absent.
- `gate.sh`: local release gate and pre-push hook installer.

### Not changed

Fresnel, curvature, thresholds, sample count and the online source are unchanged. A local DEM changes results by source (a different model, vintage and datum); the evidence must name it, which `elevation_source` allows. Whether a local raster is a surface or bare-earth model is not known to this package.

## [0.2.0] - 2026-10-08

### Changed -- clearance results are different (please re-run saved analyses)

- **Earth curvature is now applied in the correct direction.** Previously the effective-earth bulge was subtracted from the terrain
  elevation, which *added* clearance; it is now added to the terrain, i.e. subtracted from the geometric clearance
  (`terrain_adjusted = ground + bulge`). Clearance values from 0.1.0 were therefore too high.
- **Size of the change.** At a point `d1` km from one end and `d2` km from the other the change is `2 * d1 * d2 / (2 * k * R)` metres
  (twice the bulge). At the middle of a path of `D` km that is approximately `D^2 / (4 * k * R)` metres lower than 0.1.0 (k = 4/3,
  R = 6371 km): about 1 m at 6 km, 5 m at 13 km, 15 m at 23 km, 43 m at 38 km and 294 m at 100 km. Short paths barely change; long paths can
  change class (`clear` / `marginal` / `obstructed`). The endpoints are unchanged. Example: flat ground, 30 m masts at both ends, 38.1 km,
  6.35 GHz: tightest clearance 8.6 m (0.1.0: 51.4 m).
- `ProfilePoint.terrain_adjusted_m` is now `ground_elevation_m + earth_bulge_m` (it was `ground_elevation_m - earth_bulge_m`).
  `clearance_m`, `terrain_clearance_m`, `percent_fresnel_clear`, `los_status`, `near_threshold`, the explanation text and the batch/GeoJSON
  output follow from it.
- This release corrects the sign of the curvature term only. The Fresnel formula, the k = 4/3 default, the 60 % / 30 % limits, the
  elevation sampling and the elevation source are unchanged, and this release does not validate the propagation model as a whole.
  The sign was checked against an independent straight-line geometry on an effective-radius earth (agreement within 0.02 m on paths of
  10, 38.1, 100 and 203 km); see `tests/test_curvature_convention.py`.

### Added

- `aei_link_clearance.terrain.CLEARANCE_CONVENTION` (`"bulge-added-to-terrain"`), so a program that depends on this package can detect the
  convention in use. Releases before 0.2.0 do not define it.
- `aei_link_clearance.elevation.ElevationDataError` (a subclass of `ValueError`).

### Fixed

- `get_elevations()` now raises `ElevationDataError` if the elevation service returns a missing, `null`, NaN, infinite or non-numeric value,
  instead of passing it on. The existing wrong-number-of-values error is now also an `ElevationDataError`; code that catches `ValueError`
  is unaffected.
